## 조합과 스택

### 조합은 일하는 방식 4개, 스택은 자동
- 결정: 가볍게·혼자 빠르게·팀 협업·꼼꼼하게. 스택별 스킬·언어별 훅은 감지 결과로 더한다. 가볍게는 「안전장치만」.
- 이유: 스택마다 조합을 만들면 고를 것이 너무 많아진다.
- 인프라: Terraform(맨 위·infra/·terraform/·iac/·deploy/ 의 .tf), Kubernetes(Chart.yaml·kustomization.yaml·k8s/·kubernetes/·charts/*/Chart.yaml), Ansible(ansible.cfg·playbooks/) — 종류 infra, ask-cmd 를 더한다.
- 감지 범위(역할극 2~6 회차·독립 검토, 2026-11-11): 맨 위 + src/·packages/·apps/·libs/·services/ 하위 + package.json workspaces·pnpm-workspace.yaml 경로(상한 200). JS 스택은 패키지마다 판정해 합친다(웹·모바일 모노레포에서 React 가 사라지지 않게). Python 은 의존성 칸만 읽는다 — requirements*.txt·requirements/*.txt(주석 뺌), pyproject 의 dependencies·optional-dependencies·dependency-groups·tool.poetry·tool.uv, setup.py·setup.cfg install_requires, Pipfile, conda environment.yml — 이름을 통째로 맞춘다(설명·keywords·주석 글에 걸리지 않게). ROS 2 는 package.xml 의 ament(buildtool_depend 또는 build_type — ament_python 템플릿)로, 맨 위·맨 위 하위·src/*·src/*/* 에서 찾는다(상한 300). C/C++ 는 맨 위 CMake·meson·ROS 패키지의 CMake·맨 위 Makefile 과 C 소스만(하위 vendored CMake 는 보지 않음). iOS 의 project.yml 은 맨 위만. iOS 는 앱 단서가 있을 때만: Podfile, Xcode 프로젝트(git 이 아는 *.xcodeproj/project.pbxproj·*.xcworkspace/contents.xcworkspacedata 는 깊이 상관없이 — KMP 의 iosApp/, 아니면 맨 위·패키지 폴더의 폴더 이름), 맨 위 .xcode-version, `.iOS(` 플랫폼을 적은 Package.swift, git 이 아는 Info.plist 와 Swift 소스 셋 이상(Pods·Carthage·.build·vendor 밖). Package.swift 만·Swift 소스만(Vapor 서버·SPM 라이브러리·명령줄 도구)은 iOS 가 아니라 스택 Swift — Package.swift 가 있거나, Swift(·Objective-C)가 가장 많은 언어이고 다른 주 언어 스택(package.json·Go·Python·JVM·C/C++ 등)이 없을 때(React + tools/mac-helper/*.swift, Go 서버 + clients/swift/ 는 아님, 독립 검토·검토 2026-11-13). 소스·인프라·Info.plist·Xcode 프로젝트 파일은 git ls-files 한 번으로 본다(Swift 만 따로 부르니 파일 2만 개에서 35% 느려졌다). 단 RN·Expo·Flutter·Capacitor·Cordova 저장소는 ios/ 가 껍데기라 보지 않는다(2026-11-13). Terraform 은 .tf 와 OpenTofu .tofu. Postgres 는 의존성·Prisma provider·compose 이미지 이름(postgres·postgresql·pgvector·postgis)으로. 그 밖에 Claude API·MCP·Slack·MuJoCo·wandb·Hydra·scikit-learn·Jupyter, 종류 robotics. ### 조합 기본값을 저장소에 맞춘다 (검토 뒤 사용자 승인, 2026-11-09)
- 개인 습관 훅은 기본 꺼짐: commit-hash·work-checklist·docs-check 를 모든 조합에서 뺐다(고를 수는 있음). 커밋 해시·체크리스트는 업계 관례가 아니라 개인 습관이고 체크리스트는 Claude Code 할 일 목록과 겹친다. 문서 형식 검사는 제목·날짜 줄·목차까지 막아 엄격하다.
- 형식 훅은 저장소가 이미 그 꼴일 때만: `scripts/detect.mjs` 가 merge 아닌 최근 커밋 제목 30개와 로컬·원격 브랜치 이름을 읽고(`history`), `fitOff` 가 commit-msg 훅과 같은 정규식으로 70% 미만이면 commit-msg 를, 브랜치 전략마다 그 꼴로 main·master·develop·기본 브랜치를 뺀 이름이 70% 미만이면 branch-name 을 기본에서 뺀다. 커밋 5개·브랜치 3개 미만이면 새 저장소로 보고 켠다. 훅 단계·auto 보고에 뺀 이유 한 줄. 사용자가 켜면 그대로 켜진다.
- pin-deps 는 꼼꼼하게에서만, 라이브러리 패키지는 뺀다: `main`·`exports`·`types`·`typings` 가 있고 `private: true` 가 아니면 라이브러리. 라이브러리가 정확한 버전으로 고정하면 쓰는 쪽에 같은 패키지가 여러 벌 깔리고 보안 패치도 못 받는다. 앱도 고정은 팀 취향이라 팀 협업 기본에서 뺐다.
- 볼 파일이 없는 훅은 기본에서 뺀다(역할극 2~6 회차, 2026-11-11): package.json 이 없으면 unsafe-html(JS·TS·HTML·서버 템플릿만 본다 — .jinja·.j2·.njk 도 있으면 켠다), `.github/workflows` 에 yml 이 없으면 gha-inject(빈 폴더는 GitHub Actions 로 치지 않는다). 지침도 같이 — `{{kind:web|backend}}` 를 단 줄(HTML 이스케이프·로그인 검사)은 그 종류 저장소에만. JS 여부는 package.json(하위 패키지 포함) 또는 git 이 아는 JS·TS·HTML 파일로 본다(정적 사이트·Django 템플릿). 종류를 모르는 저장소(general)는 웹·서버 줄도 넣는다(KIND 표에 없는 백엔드에서 보안 줄이 빠지지 않게). 화면도 같은 옵션 기본값을 쓴다(`picker/selection.js` fromCombo).
  - 2026-11-13 전체 검토: 앱 코드가 없으면(code: false — 인프라만) general 을 두지 않는다 — 모르는 앱이 아니라 앱이 없다(15 회차에 로그인 검사 줄). .xcodeproj·.xcworkspace 만 있는 앱도 iOS(모바일)로 읽는다(16 회차는 iOS 를 몰라 general 이 됐다, `scripts/detect.mjs` — 다른 갈래가 고치는 파일이라 두 줄만). JS·TS 는 있어도 화면 파일(kinds 의 html — HTML·서버 템플릿·JSX/TSX·Vue 등)이 없고 웹 스택도 아니면 unsafe-html 도 뺀다(6 회차의 TS 에이전트). eval 도 보는 훅이라 이유 글(fitNoUi)에 켤 수 있다고 적는다.
- 커밋 기록이 한 언어로 70% 넘으면 commit-msg 의 `lang` 을 그 언어로 켠다(5개 미만이거나 섞이면 정하지 않음). 기록이 다 한국어인데 「언어는 보지 않음」으로 들어가던 일. 봇(dependabot·renovate·[bot]) 커밋은 세지 않고, 영어는 본문에도 한글이 없을 때만 센다(commit-msg 의 en 은 본문의 한글도 막아서).
- 이유: 안 따르는 저장소에 켜면 첫 커밋·첫 브랜치부터 막혀 「도구가 고장 났다」로 읽힌다. 볼 것이 없는 훅·줄은 「관련 없는 추천」으로 읽힌다.
- 어디서: `scripts/lib/catalog.mjs` 의 `fitOff`·`fitDropped`·`commitLang`, `scripts/detect.mjs`(`history`·`js`·`workflowFiles`), `scripts/lib/rule-files.mjs` 의 `TAG`·`kindFits`, `hooks/rules/message.mjs` 의 `CONVENTIONAL`, `scripts/test/defaults.test.mjs`

## 저장소 단서

### 묻는 명령·보호 경로 미리 채우기 (역할극 10~15 회차, 2026-11-11~12)
- 저장소 단서(scripts/lib/suggest.mjs)를 넓혔다:
  - 보호 경로: .gitignore 에서 바로 위 주석이 비밀·개인정보·never commit 이라고 한 묶음(빈 줄까지 — 빌드·로그·캐시 결과물은 뺌), `*.env` 이름(lab.env), dbt 저장소의 profiles.yml, 확장자 하나 글롭(`*.evtx` → `.evtx`). .env·키 파일처럼 늘 막는 것은 넣지 않는다(자리만 차지해 .pcap 이 밀렸다).
  - 실행 전에 묻기: Makefile 대상 가운데 레시피가 원격 스크립트를 부르거나 원격 명령·운영 옵션(--env prod·--target prod)을 쓰는 것(make deploy-prod·make backfill — dry·plan 이름과 DRY_RUN=1 레시피는 뺌), 그 운영 명령 자체(detctl deploy --env prod, 스크립트 속 dbt build --target prod — ask-cmd 가 옵션 자리를 가리지 않으므로 앞 낱말 + 운영 옵션만 적는다). 원격 스크립트 판정은 훅과 같은 함수(remote-cmd.mjs)로 — 읽기만 하는 kubectl get·terraform plan 은 아니다 — 에 배포 도구 몇 가지(firebase deploy·vercel --prod·wrangler deploy·git push heroku 등)를 더했다.
- 배포 플랫폼: vercel.json·.vercel/project.json·netlify.toml·firebase.json·fly.toml 이 있으면 그 운영 배포 명령(vercel --prod·promote·rollback·env, netlify deploy --prod, firebase deploy, fly deploy·secrets)을 ask-cmd 에 미리 채운다.
- 화면의 브랜치 방식이 fitOff 로 뺀 훅(GitLab 의 pr-merge)을 다시 켜지 않는다. 미리 채운 배포 명령은 바꾸는 하위 명령만(vercel env add·rm, fly secrets set·unset — env pull·secrets list 까지 묻던 것), netlify 는 env:set 꼴.
- 저장소 위치: origin 이 없으면 .gitlab-ci.yml·.gitlab/·go.mod 의 module gitlab.… 로 GitLab 을 안다. GitLab 이면 GitHub 전용 훅(prefer-gh·pr-merge)은 fitOff 로 기본에서 빼고(이유 줄이 남는다) pr-writer 스킬도 뺀다(catalog/combos.json githubOnly).
- 감지: 맨 위 바로 아래 폴더의 빌드 파일(enricher/go.mod — 12 회차), Gradle 여러 줄 include·주석, dbt·PySpark·Airflow·Kafka(Python). compose 이미지만의 Postgres 는 앱이 표를 만드는 저장소(ORM·마이그레이션 도구·웹 프레임워크)에서만 — 로컬 시험용 DB(dbt 의 로컬 대상, 웨어하우스는 Redshift)에 Supabase·Postgres 스킬이 붙었다(10 회차).
- 지침 줄: 「HTML 이스케이프」는 HTML·템플릿 파일이 있을 때만(kinds 의 html 은 파일로 확인한 것이라 general 이어도 없으면 뺀다 — 12 회차). 「정확한 버전」(pin-deps 꺼짐)은 JS 저장소만 — Cargo·Spring BOM 관례와 부딪쳤다(8·11 회차).
  - 「정확한 버전」은 kinds 의 pinned(JS 저장소, 라이브러리 아님, package.json 의존성이 넷 이상이면서 절반 넘게 ^·~ 범위가 아님)일 때만. 범위가 관례인 저장소는 의존성 고정 훅도 fitOff 로 기본에서 뺀다(이유 fitPinRanges) — 줄과 훅이 같은 기준(13 회차). `scripts/lib/signals.mjs` depRanges.

### 「이 저장소 명령」 감지 세부 (역할극 4·8·9·13·14·15 회차, 2026-11-11~12)
- pyproject `[project.scripts]`·`[tool.poetry.scripts]` 를 「이 저장소가 설치하는 명령」 줄로(평가·수집 명령이 빠지던 일 — 4 회차 2차). `scripts/lib/commands.mjs` tools.

- 명령(README·CI, 2026-11-13 — 3 회차 eval.py, 11 회차 시드 재현·miri·fuzz·빠른 벤치·plot.py): README·CONTRIBUTING·DEVELOPMENT·NOTES.md 의 셸 블록과 글 속 `…`, GitHub Actions `run:` 줄을 맨 뒤 차례로(`scripts/lib/doc-commands.mjs`, 8개까지). python 스크립트·모듈과 cargo 하위 명령만, 그 파일·`-p` 패키지·`--test`·`--bench`·fuzz 대상이 있을 때만. 설치·배포·출시 제목 아래, 배포·출시 워크플로·작업·단계, 이음·`$(`·`${{`, 운영 옵션·운영 값 환경 변수(ENV=prod), 운영·지우기 낱말(deploy·publish·migrate·seed·wipe·sync…)이 든 이름·인자, manage.py·setup.py·셸 스크립트·make 는 읽지 않는다(독립 검토 2026-11-13). 이미 찾은 명령에 인자만 더한 꼴은 빼고, 묻는 명령에 든 것은 지침에서 빠진다(withoutAsked).
- README·CI 명령은 넣는 쪽을 좁게(두 번째 독립 검토 2026-11-13). 이 목록은 Claude 에게 「평소 돌려도 되는 명령」이라고 알리니, 안전한 명령을 빠뜨리는 것보다 위험한 명령을 넣는 것이 훨씬 나쁘다. 낱말 목록을 하나씩 덧대지 않고 이름·인자·옵션·끝 주석을 모두 조각(_ - . / 와 camelCase)으로 나눠, 조각이 위험한 낱말 뿌리(migrat·deploy·ship·drop·reset·flush·clean·seed·sync·rebuild·prod…)로 시작하면 뺀다(`scripts/lib/doc-risk.mjs`). 그래서 run_migrations.py·deployModel.py·--drop-existing·--env=PROD·$PROD_URL 도 빠진다. 난수 시드(--seed 42)·dropout·cargo --release 는 둔다.
  - 끝 주석에 주의 낱말(warning·never·prod·주의·운영·조심…)이 있으면 뺀다. 글 속 `…` 는 그 줄에, 코드 블록은 바로 앞 글 줄에 주의·부정 낱말이 없을 때만.
  - 제목은 깊이를 따른다(「## Deployment」 아래 「### Steps」 도 건너뜀). 밑줄 제목(----·====)도 제목. README.rst 는 읽지 않는다(꼴이 달라 설치·배포 제목을 못 알아본다).
  - 워크플로는 워크플로·작업·단계를 통째로 나눈 뒤 정한다(단계 끝의 name: Deploy·steps: 뒤 작업 name: 을 늦게 봤다). environment: 가 있는 작업, cd.yml, 태그 push·release 로 도는 워크플로, if: 가 태그를 보는 작업·단계, run 밖 설정에 운영 조각이 든 작업·단계는 읽지 않는다(`scripts/lib/doc-workflows.mjs`).
  - 정규식은 줄 길이(120자)를 먼저 보고, 여러 줄 정규식(Cargo.toml name)·`\s` 로 줄바꿈까지 먹는 꼴(#[ignore])은 한 줄씩 읽기로 바꿨다(빈칸·빈 줄 수만 개에서 3~12초). 파일은 앞부분만 읽는다(readText 상한). Cargo 패키지는 [workspace] members 만 본다.
- 결과를 지킬 경로에 쓰는 명령은 뺀다(두 번째 독립 검토 2026-11-13). suggest 의 protect(.gitignore 의 data/·.hdf5)를 detectCommands 가 받아 README·CI 명령에 넘긴다. 쓰는 쪽 인자만 본다 — -o·--out·--output·--output-dir·--save·--dest·--dump 의 값과 out=·output_dir=·save_path=·dest= 의 값. 읽는 쪽 인자(dataset.path=data/x.hdf5)는 그대로 둔다(학습 명령이 거의 다 빠진다).
- 명령(뒤): Makefile 이 시험·검사·빌드를 맡으면 언어 기본값(go test ./...·cargo test)은 내지 않고, 하나만 돌리기는 make test 레시피의 결과를 바꾸는 옵션(-race·-count·-tags)을 따른다. 이미 CLAUDE.md 에 있는 명령을 거른 뒤 개수를 자른다(적어 둔 명령이 자리를 먹어 make migrate-new 가 밀렸다). 「그 밖의 명령」 지침은 파일 이름을 늘어놓지 않는다(Go 저장소에 pyproject·manage.py 가 나왔다).
- 명령(13·15·16 회차, 2026-11-13): .pre-commit-config.yaml → 검사에 `pre-commit run -a`, Playwright → `<pm 실행> playwright install`, Fastfile 의 test 레인 → `bundle exec fastlane test`(Gemfile 있을 때), 검사 명령이 없고 .swiftlint.yml 만 있으면 `swiftlint lint`. 검사 줄에도 「끝내기 전에」. 묻는 명령(ask-cmd commands, 저장소에서 찾은 것이 앞 — 5개까지)은 평소 목록에서 빼되 「사람이 직접 실행하는 명령」 한 줄로 남긴다(`{{cmd:asked}}` — 뺀 흔적이 없어 make apply-*·release.sh 가 사람 몫이라는 표시가 없었다). Xcode 시험 폴더(<이름>Tests/)도 hasTests, .swiftlint.yml 은 스택 SwiftLint(도구 스택 — thin 판정에서 세지 않음).
- Makefile 읽기는 scripts/lib/makefile.mjs 한곳(대상·변수·레시피 —  이어 쓴 줄, test::, 한 줄 여러 대상). 언어 기본값(go test ./...·cargo test)은 make 대상의 레시피가 그 도구를 부를 때만 뺀다(build: 가 docker build 면 go build ./... 를 남긴다).
- Makefile(셋째 검토): 레시피 사이 ifeq·else·endif 는 레시피를 끊지 않고 주석 줄은 빼며, 의존 대상(test: test-unit)의 레시피·gotestsum -- 옵션·경로로 부른 go·golangci-lint 도 따른다. 마이그레이션을 되돌리는 대상(migrate-down·db-rollback)은 쓸 명령에서 빼고 묻는 명령에 넣는다(화면 평가 — goose down 이 쓸 명령에 있었다). 앱 코드 세기에서 .github/·docs/ 의 스크립트는 빼고, git 저장소가 아니면 빼지 않는다.

### 커밋한 결과·논문 폴더는 적용 때 묻는다 (사용자 결정 「적용 때 물어보기」, 2026-11-13)
- 결정: git 이 추적하는 결과·논문 폴더는 선택에 말없이 넣지 않고, 적용할 때 파일 보호(protected-files paths)에 넣을지 묻는다. ROS 2 관절 한계·URDF 와 같은 길 — setup 스킬이 같은 질문 안에서 묻고, 사용자가 고른 경로만 넣는다. 고르기 화면 흐름에서는 스킬이 화면을 연다는 줄에 같이 알리고, 사용자가 「더 지킬 파일·폴더」에 넣으면 칩에 같은 까닭이 보인다(picker/opt-list.js — offer 목록도 까닭을 찾는다).
- 이유: 11 회차 M3(bench-results/ 숫자·paper/figures/runs.txt 를 손으로 고치지 않기)·M5(paper/*.tex·refs.bib 는 허락 없이 고치지 않기)가 처음 추천에 없었다. 그렇다고 바로 넣으면 사용자가 손으로 다듬는 원고·결과까지 Claude 가 못 고치게 되니 묻는다.
- 무엇을: 맨 위 기준 results/·bench-results/·benchmark-results/·benchmarks/results/·bench/results/·experiments/results/ 가 데이터·문서 파일(csv·tsv·txt·json·parquet·npz·그림·md 등)만 들었을 때 폴더째. 논문 폴더(paper/·papers/·manuscript/·thesis/)에 .tex·.bib 가 있으면 — 원고·그림·자료만 들었으면 폴더째, 그림을 만드는 코드(plot.py)가 섞이면 `paper/**/*.tex`·`paper/**/*.bib` 와, 같은 폴더 스크립트가 이름으로 읽는 글 자료 파일(runs.txt — 4개까지). 맨 위 figures/ 는 근거가 있을 때만(스크립트가 `figures/` 를 적거나 .gitignore 주석이 말함 — 문서 그림 폴더가 흔하다).
- 까닭(why.k, 화면 문구 srcWhy_<k>): results(그 폴더를 적은 스크립트 — run_bench.sh 의 `OUT="bench-results/…"`)·results-note(.gitignore 주석)·results-dir(근거 없이 이름·내용으로만)·paper·figure-data(읽는 스크립트)·figures·figures-note. 폴더 이름은 맨 위 기준 경로로, 뒤에 `/`·따옴표가 올 때만 근거로 센다(주석 속 「raw results are …」, benchmarks/results/ 의 results 는 아님).
- 아님: 소스 파일이 하나라도 든 폴더(이름만 results 인 Python·Go 패키지), git 이 추적하지 않는 파일(무시 목록의 결과 폴더는 .gitignore 단서 쪽 일), README 만 든 폴더, .tex·.bib 없는 paper/, 하위 폴더의 results/(src/results/), git 저장소가 아님. 모르는 확장자가 하나라도 있으면 폴더째 내지 않는다.
- 결과·논문 폴더 묻기(`record-folders.mjs`): 논문 폴더가 추적 파일의 절반을 넘으면(학위 논문 저장소) 묻지 않는다 — 원고를 지키면 할 일을 막는다. 웹사이트 저장소(맨 위 index.html·_config.yml·hugo.*·_quarto.yml·mkdocs.yml·.nojekyll, Gemfile 의 jekyll·github-pages, config.toml + content/ + layouts|themes/)의 papers/*.bib 는 출판 목록이라 묻지 않는다. 결과 폴더에 기대값 이름(expected·golden·snapshot·fixture) 파일이 있거나 시험 파일(60개까지)이 그 폴더를 적으면 시험 자료라 묻지 않는다. git ls-files 는 여전히 한 번(이제 전부 — 비율·시험 파일을 보려고). 11 회차의 bench-results/·paper 원고·runs.txt 는 그대로 묻는다.
- 어디서: `scripts/lib/record-folders.mjs`(git ls-files 한 번), `suggest.mjs` 의 `offer`(있을 때만 칸이 생긴다 — 이미 protect 에 있는 값은 뺀다), `detect.mjs --brief` 의 `offer`(값 → 까닭), `skills/setup/SKILL.md`. 시험 `scripts/test/record-payments.test.mjs`.
