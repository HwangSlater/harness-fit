## JS 파일을 셸 스크립트로 고치지 않는다
- 증상: python·node 인라인 스크립트(heredoc 안 문자열 치환)로 .mjs 를 고치다 `\b`·`\n`·`\s` 가 백스페이스·줄바꿈으로 바뀌어 정규식이 깨졌다. 이번 세션에서만 4번(git.mjs, shell.mjs, tokens.mjs, apply.mjs).
- 할 것: 코드 수정은 Edit/Write 도구로. 여러 곳을 한꺼번에 바꿔야 하면 파일 전체를 Write 로 다시 쓴다. JSON 데이터만 node 로 고친다(문자열 이스케이프가 없는 것).

## 화면 문구는 실제 동작과 같은 데이터에서 만든다
- 증상: 「브랜치 방식을 고르면 관련 검사도 같이 맞춰져요」라고 써 놓고 실제로는 훅이 안 바뀌었다. CLAUDE.md 에는 꺼 둔 훅을 「훅이 검사」라고 적었다. 사용자 역할 평가에서 두 사람 모두 짚었다.
- 할 것: 설명 문구를 쓸 때 그 약속을 지키는 코드가 같은 데이터(packs.json 등)를 보고 있는지 확인한다. 사용자 역할 에이전트 평가를 화면을 바꿀 때마다 돌린다.

## 훅의 명령 읽기는 bash 와 PowerShell 을 둘 다 생각한다
- 증상: 따옴표 속 글을 비우는 코드가 `\"` 를 이스케이프로 읽어, PowerShell 의 `git -C "C:\repo\" commit -n` 에서 뒤 명령 전체를 따옴표 속으로 보고 검사를 통째로 건너뛰었다. `rm` 은 PowerShell 에서 Remove-Item 별칭이라 `-Recurse -Force` 꼴도 봐야 했다.
- 이어서: 「bash 로 먼저 읽고 안 맞으면 PowerShell 로 다시 읽기」로 고쳤더니 `".\out\"` 같은 상대 경로 두 개가 짝을 이뤄 그 사이 위험 명령이 가려졌다(3차 검토).
- 할 것: 셸은 짐작하지 말고 훅 입력의 도구 이름(`tool_name`: Bash/PowerShell)으로 정한다(hooks/lib/quotes.mjs). 명령을 읽는 규칙을 바꾸면 셸마다 「막아야 할 것」과 「통과해야 할 것」을 함께 시험에 넣는다(hooks/test/review2·review3.test.mjs). 정규식 하나보다 낱말 단위로 읽는다.

## 되돌리기는 저장소에 있는 백업 목록을 믿지 않는다
- 증상: 백업 목록(manifest)의 경로를 그대로 지우고 덮어써서, 저장소에 심어 둔 목록 하나로 프로젝트 밖·`.git/hooks` 를 건드릴 수 있었다. 적용 뒤 사용자가 고친 .gitignore(`.env` 줄)까지 통째로 지웠다.
- 할 것: 적용이 만들 수 있는 경로만 허용하고, 쓴 내용의 지문과 비교해 사용자가 고친 것은 따로 남긴다(scripts/lib/backup.mjs).
