# 교훈

## JS 파일을 셸 스크립트로 고치지 않는다
- 증상: python·node 인라인 스크립트(heredoc 안 문자열 치환)로 .mjs 를 고치다 `\b`·`\n`·`\s` 가 백스페이스·줄바꿈으로 바뀌어 정규식이 깨졌다. 이번 세션에서만 4번(git.mjs, shell.mjs, tokens.mjs, apply.mjs).
- 할 것: 코드 수정은 Edit/Write 도구로. 여러 곳을 한꺼번에 바꿔야 하면 파일 전체를 Write 로 다시 쓴다. JSON 데이터만 node 로 고친다(문자열 이스케이프가 없는 것).

## 화면 문구는 실제 동작과 같은 데이터에서 만든다
- 증상: 「브랜치 방식을 고르면 관련 검사도 같이 맞춰져요」라고 써 놓고 실제로는 훅이 안 바뀌었다. CLAUDE.md 에는 꺼 둔 훅을 「훅이 검사」라고 적었다. 사용자 역할 평가에서 두 사람 모두 짚었다.
- 할 것: 설명 문구를 쓸 때 그 약속을 지키는 코드가 같은 데이터(packs.json 등)를 보고 있는지 확인한다. 사용자 역할 에이전트 평가를 화면을 바꿀 때마다 돌린다.

## 훅의 명령 읽기는 bash 와 PowerShell 을 둘 다 생각한다
- 증상: 따옴표 속 글을 비우는 코드가 `\"` 를 이스케이프로 읽어, PowerShell 의 `git -C "C:\repo\" commit -n` 에서 뒤 명령 전체를 따옴표 속으로 보고 검사를 통째로 건너뛰었다. `rm` 은 PowerShell 에서 Remove-Item 별칭이라 `-Recurse -Force` 꼴도 봐야 했다.
- 이어서: 「bash 로 먼저 읽고 안 맞으면 PowerShell 로 다시 읽기」로 고쳤더니 `".\out\"` 같은 상대 경로 두 개가 짝을 이뤄 그 사이 위험 명령이 가려졌다(3차 검토).
- 할 것: 셸은 짐작하지 말고 훅 입력의 도구 이름(`tool_name`: Bash/PowerShell)으로 정한다(hooks/lib/quotes.mjs). 명령을 읽는 규칙을 바꾸면 셸마다 「막아야 할 것」과 「통과해야 할 것」을 함께 시험에 넣는다(hooks/test/review2·review3.test.mjs). 정규식 하나보다 낱말 단위로 읽는다.

## 되돌리기는 저장소에 있는 백업 목록을 믿지 않는다
- 증상: 백업 목록(manifest)의 경로를 그대로 지우고 덮어써서, 저장소에 심어 둔 목록 하나로 프로젝트 밖·`.git/hooks` 를 건드릴 수 있었다. 적용 뒤 사용자가 고친 .gitignore(`.env` 줄)까지 통째로 지웠다.
- 할 것: 적용이 만들 수 있는 경로만 허용하고, 쓴 내용의 지문과 비교해 사용자가 고친 것은 따로 남긴다(scripts/lib/backup.mjs).

## 일하는 방식을 바꾸자고 할 때는 무엇이·왜 바뀌는지 같이 적는다
- 증상: 「끝내기 전 확인」 스킬을 훅으로 바꾸자고 제안하면서 이유를 적지 않아, 사용자가 「스킬에서 갑자기 훅으로 변하네. 이유도 안 적혀 있고」라고 되물었다(2026-11-06). 같은 보고에서 「다시 실행할 때 이전 선택 이어 쓰기」, 「허용 주석·CSS 색」도 무슨 뜻인지 되물음을 받았다.
- 할 것: 글(스킬·규칙)을 검사(훅)로 바꾸거나 그 반대일 때는 지금 어떻게 되어 있는지, 바꾸면 무엇이 달라지는지, 근거(기록·숫자), 위험(헛막음)을 함께 적는다. 결정을 부탁하는 항목은 실제로 겪는 장면 하나로 설명한다. 화면 문구도 같다 — 검사로 막는 것은 왜 글이 아니라 검사인지 한 줄로 보인다.

## 훅은 「정밀하게」가 아니라 「약속한 것을 빠짐없이」 잡을 때만 만든다
- 증상: SQL·셸 주입, 로그 비밀값, 값 바로 적기 훅을 「헛막음이 적게」 맞춰 만들고, 훅이 켜지면 그 규칙 글을 지웠다. 셋 다 짐작(SQL 낱말이 있으면, 이름에 password 가 들어가면, 설정 같은 파일 이름은 빼고)으로 거르는 훅이라 놓친 것은 훅에도 글에도 없게 됐다. 사용자 지적(2026-11-06): 「훅도 100프로 잡을 수 있어야 의미가 있다」, 「훅은 전부 테스트 엄격하게」.
- 할 것: 훅을 만들기 전에 「이 훅이 약속하는 것(packs.json detail)을 빠짐없이 잡는가」를 먼저 따진다. 짐작해야 하면 훅을 만들지 않고 짧은 규칙 글로 둔다. 훅이 규칙 한 줄의 일부만 덮으면 그 줄은 지우지 않는다. 훅마다 약속한 꼴 전부를 막는 시험과 비슷한 꼴을 통과시키는 시험을 실제 진입점(hooks/run.mjs)으로 돌린다. 셸로 파일을 쓰면 쓰기 훅은 못 보므로 커밋 때 다시 본다.

## 훅은 터짐·느림을 진입점으로 시험한다
- 증상: 엄격 사례는 다 통과했는데 crash 시험(hooks/test/crash.test.mjs)에서 `git -c git -c …` 10만 자가 한 번에 100초 넘게 걸렸다(git 찾는 정규식이 값마다 다시 시작해 길이의 제곱). 닫히지 않은 `${{ ${{ …` 워크플로 3초, 10MB 파일 쓰기 8초(줄마다 정규식을 새로 만들고 10개씩 돌림), 새 파일 2000개 커밋은 파일마다 `git show` 를 띄워 몇 분. git 을 부를 때 `timeout`·`windowsHide` 를 주자 Windows 에서 한 번이 70ms → 250ms 가 됐다.
- 할 것: 정규식을 더하면 그 정규식이 맞을 듯 말 듯한 글을 10만 자 되풀이해 run.mjs 로 시간을 잰다(crash.test.mjs 의 REDOS 목록에 더한다). 「다음 것을 넘지 않는」 꼴(`[^}$]`, 앞 옵션 값에서 다시 시작하지 않는 lookbehind)로 쓰고, 큰 글은 꼭 있어야 하는 조각으로 먼저 거른다. git 은 파일마다가 아니라 한 번에 묻는다(`--numstat`, `--diff-filter=A`). 훅에서 띄우는 프로세스 옵션을 바꾸면 bench 로 전후를 잰다.

## 서브에이전트 작업 공간은 어느 커밋에서 갈라졌는지 먼저 본다

2026-11-06: 같이 띄운 작업 공간 둘 중 하나가 지금 갈래가 아니라 `main`(v0.2.2)에서 갈라져, 다 만든 뒤 옮기려니 9개 파일이 충돌했다(그 사이 들어간 훅 옵션·GitHub 설정을 모르는 코드). 다른 하나는 맞는 곳에서 갈라졌는데 확인 없이 같이 멈춰 다시 시켰다. 띄운 뒤 바로 `git log -1` 로 바탕을 보고, 지금 갈래가 아니면 그 자리에서 고친다. 갈래가 중요하면 작업 공간을 직접 만들어(`git worktree add <경로> -b <이름> <갈래>`) 그 경로만 쓰게 한다. 멈추기 전에는 둘 다 따로 확인한다.

## 기존 훅 시험은 홈·설정 폴더 환경 변수를 모두 임시 폴더로 돌린다

2026-11-06 검토: Stop 등 때의 시험만 HOME·USERPROFILE 을 바꾸고, 도구 시험(PreToolUse)은 실제 홈으로 사용자 훅을 수십 번 돌려 로그·상태를 남기는 훅이 시험 기록을 사용자 홈에 쌓았다. APPDATA·LOCALAPPDATA·XDG_*·CLAUDE_CONFIG_DIR 도 그대로였다. 시험은 어느 때든 `spaceEnv`(scripts/lib/probe-run.mjs)로 이 변수를 모두 임시 폴더로 바꾸고(대소문자만 다른 같은 이름도 지움), 명령 속 `~`·`$HOME`·`%USERPROFILE%` 같은 스크립트 경로만 실제 값으로 펼친다(안 펼치면 스크립트를 못 찾아 「통과」로 읽혀 겹침을 놓친다). 시간이 넘은 훅은 손자까지 끝낸다. 시험 대상 훅에 새 홈 변수가 보이면 HOME_DIRS 에 더한다.

## 「적절히 적용해」는 「하나씩 따져 보고 넣을 것만 넣어」다

2026-11-07: 제안 가~라를 「적절히 적용해 달라」는 말을 「전부 적용」으로 읽고 그대로 맡겼다가 바로잡혔다. 맡긴다는 말은 판단까지 맡긴다는 뜻이라, 항목마다(지침이면 줄마다) 적용·고쳐 적용·적용 안 함을 근거(공식 문서, 실제 동작, 훅이 맡는지, 위험, 토큰)와 함께 정하고, 적용하지 않은 것도 이유를 보여 준다.
