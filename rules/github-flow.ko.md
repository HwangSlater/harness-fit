## 브랜치 전략: GitHub Flow
- `main` 은 늘 배포할 수 있게 둔다. {{judge}}
- 작업은 브랜치에서 하고 {{pr}} 로 병합한다. {{!hook:protect-branch}}
- 브랜치 이름은 `feature/…`·`fix/…` 로 시작한다. {{!hook:branch-name}}
- {{pr}} 하나에는 기능 하나(대략 400줄을 넘으면 나눈다). {{judge}}
- 스쿼시 병합하고, 병합한 브랜치는 지운다. {{!hook:self-merge}}
- 작업을 마치면 브랜치에 커밋까지 하고 바뀐 것을 보여 준 뒤 멈춘다. push 와 {{pr}} 열기는 사용자가 올리라고 할 때만 한다. {{judge}}
- {{pr}} 을 연 뒤 병합·승인은 팀원이 한다 — Claude 는 병합·승인·자동 병합 예약을 하지 않고, 로컬에서 합쳐 보호 브랜치로 바로 올리지도 않는다. {{hook:self-merge}}
